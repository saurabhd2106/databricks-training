# GitHub Actions CI/CD

The workflow at [`.github/workflows/actuarial-claim-pipeline.yml`](../.github/workflows/actuarial-claim-pipeline.yml)
(**Actuarial claim pipeline**) runs manually via `workflow_dispatch`. It executes
test → validate → deploy/run → smoke against the `prod` target.

## 1. Create a Databricks personal access token (PAT)

1. Open the workspace: https://adb-7405611775215693.13.azuredatabricks.net
2. Click your user icon (top right) → **Settings**.
3. Under **User** → **Developer** → **Access tokens** → **Generate new token**.
4. Set a name and lifetime, then generate and copy the token (it is shown only once).

The token identity must be able to deploy the bundle, run `actuarial_claims_job`,
and access Unity Catalog for tests (prod deploys under
`databricks-np@saurabhuptut.onmicrosoft.com`).

## 2. Add GitHub repository secrets

1. Open the GitHub repository in the browser.
2. Go to **Settings** → **Secrets and variables** → **Actions**.
3. Click **New repository secret** and add:

| Name | Value |
|------|--------|
| `DATABRICKS_HOST` | `https://adb-7405611775215693.13.azuredatabricks.net` (no trailing slash) |
| `DATABRICKS_TOKEN` | the PAT you copied |

4. Save each secret.

## 3. Run the workflow

1. In GitHub, go to **Actions** → **Actuarial claim pipeline** → **Run workflow**.
2. Confirm the jobs can authenticate to Databricks (validate/deploy fail if secrets are missing or wrong).

## Notes

* Secrets are not visible after save. If you lose the token, generate a new one in
  Databricks and update `DATABRICKS_TOKEN`.
* Prefer a service principal (or OIDC) for long-lived CI instead of a personal PAT.
* See also: https://learn.microsoft.com/en-us/azure/databricks/dev-tools/ci-cd/github
